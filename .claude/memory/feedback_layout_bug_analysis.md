레이아웃/렌더링 버그 분석 시 반드시 아래 순서를 지킬 것.

**Why:** forum_score_manage.jsp 우측 영역 축소 현상 분석 시, 스크롤바가 "사라지는" 방향으로 가설을 세웠으나 실제는 "생기는" 방향이 문제였고, accordion jQuery UI가 실제로 동작하는지 미검증인 채로 수정안을 냈다가 사용자를 혼란스럽게 했음.

**How to apply:**

1. **현상의 방향 먼저 특정**: 줄어드는지/늘어나는지, 스크롤바가 생기는지/사라지는지를 가설 이전에 확정.

2. **스크립트 실행 타임라인 먼저 그리기** (레이아웃 버그는 필수):
   ```
   1. <head> script 실행
   2. body inline <script> 실행 (파서가 도달할 때마다)
   3. DOMContentLoaded (= document.ready)
   4. window.load
   ```
   width 측정 시점과 스크롤바 확정 시점을 타임라인에 배치한 후 가설 수립.

3. **인과 체인의 미검증 단계 명시**: 코드로 확인하지 못한 링크는 "[가정-미검증]"으로 표기. 미검증 단계가 체인에 포함된 채로 수정안 제안 금지.

4. **반증 조건 먼저 명시**: 수정 전에 "이 가설이 틀렸다면 어떤 증거가 나와야 하는가"를 먼저 제시.
